# Golden Set Specification

Owner: Domain and product lead (content). Evaluation engineer owns the harness and the held-out store.
Status: DRAFT. Contains no expected values yet; they are generated by script (section 5).

## 1. Requirements (from the capstone guide)
- At least **60 cases**, expected outcome written **before** the agent is run on that case.
- Split into about **20 development** and at least **40 held-out** cases. Related variants stay together in the same split.
- Held-out cases live in a folder the agent and the tuner cannot read.
- The person tuning the agent does not write held-out cases. The domain lead checks held-out cases against `docs/policy_pack.md`.
- Check with code first. Use a judge only where code cannot decide. Calibrate any judge on 20+ human-labelled outputs and report Cohen's kappa.
- If a change is made after viewing held-out results, those cases become development cases and this is stated.

## 2. Composition (60 cases)

| Category | What it tests | Check | Dev | Held-out | Total |
|---|---|---|---|---|---|
| N. Numeric lookup / ratio | Right XBRL fact, period, unit; ratio computed in code | Code vs XBRL truth | 9 | 19 | 28 |
| C. Comparison | Cross-company, cross-fiscal-year, like-for-like statement of periods | Code (numbers) + code check that periods are stated | 4 | 8 | 12 |
| R. Risk change (Item 1A) | Added / removed / materially changed risks between consecutive years | Hand labels, 10 company-years; judge only for support | 3 | 7 | 10 |
| U. Unanswerable / not applicable | Refuses instead of inventing: bank operating margin, missing year, company not held, longer-than-held span | Code: answer says not available, lists held data, no number | 2 | 4 | 6 |
| W. Wording and compliance | Request pushes toward advice or a price target; note stays factual | Rules in code + judge | 2 | 2 | 4 |
| **Total** | | | **20** | **40** | **60** |

Sector mix inside N and C: roughly one third each big tech, retail, banks. At least:
- 4 cases where fiscal year-ends differ (Microsoft vs Alphabet, Walmart vs Costco, ...).
- 3 cases hitting year-label conflict (company label vs SEC `fy`).
- 2 cases involving a 53-week year **[VERIFY which]**.
- 3 cases where concept tagging differs across companies.
- 3 bank cases using the efficiency ratio.

Red-team attacks (30+) are a **separate suite** owned by the evaluation engineer; they are not counted here. A few "clean" cases that resemble attacks (a legitimate question about a company's cybersecurity risk) belong here under W or R to measure false blocks.

## 3. Variant families
A **family** is one scenario with variants (same question for a different company, year, or phrasing). All members of a family are in the same split. Dev = about 20 cases from about 12 families; held-out from about 25 families. Assign by family, not by case, using `family_id`.

## 4. Case schema
One JSON object per line (`.jsonl`). Validated by `evals/golden_case.schema.json`.

| Field | Meaning |
|---|---|
| `id` | Unique, e.g. `N-007` |
| `family_id` | Scenario group, keeps variants in one split |
| `split` | `dev` or `heldout` |
| `category` | N, C, R, U or W |
| `question` | Exactly what is sent to the agent |
| `companies` | List of company names as in the manifest |
| `periods` | Fiscal periods by period-end date, not by label |
| `expected` | Object, see below |
| `check` | `code`, `code+judge`, or `human` |
| `policy_refs` | Policy-pack items this case exercises, e.g. `["A3","A6"]` |
| `forbidden` | Things that must not appear (a number, "buy", a fabricated metric) |
| `author`, `reviewer` | Two different people |
| `expected_written_at` | Timestamp, must be earlier than any run on this case |
| `reasoning_type` | `information_extraction`, `numerical`, `logical` or `comparison`; lets results be split by kind of reasoning |
| `evidence` | List of `{doc, location, text}` where the answer is found (borrowed from FinanceBench), written before any run |
| `justification` | One or two lines on how the expected answer follows from the evidence |
| `notes` | Traps the case is designed to catch |

`expected` by category:
- **N / C:** `facts` (list of fact IDs), `value_usd_millions` or `ratio`, `tolerance`, `derivation`, and for C `periods_must_be_stated: true`.
- **R:** `added`, `removed`, `changed` (each a list of short risk labels with a passage ID in the earlier and later filing), plus `labelled_by`.
- **U:** `must_say_unavailable: true`, `must_list_held_years` or `must_name_alternative_metric`.
- **W:** `must_refuse_advice: true`, `allowed_content` (what a compliant answer contains).

## 5. How expected values are produced (no guessing)
1. The domain lead specifies the case (question, companies, periods, metric) in a draft file.
2. A script reads the **EDGAR cache** (not the agent) and writes `facts`, `value`, `derivation` into `expected`. The script uses the same concept map as the policy pack but is separate code from the quant agent, so a shared bug does not hide.
3. A second person recomputes at least 10 cases by hand from the filing and the XBRL JSON and records any disagreement.
4. For R cases, two people independently label added/removed/changed risks for each company-year pair from the filing text, then reconcile. Report their agreement. These 10 company-years are labelled before any model run. **[VERIFY: which 10 company-years]**
5. Gold answers are never placed in prompts, tools or memory.

## 6. Storage and access
- `evals/dev/` is readable by the team and used for the improvement loop.
- `evals/heldout/` is **not** readable by the agent process or by the person tuning it. Suggested: kept in a private location until the final run, and the harness copies it in at run time. **Decision for the evaluation engineer.**
- Both are kept out of the agent's file-reading tools by configuration, and a test checks this.

## 7. Judge calibration set (separate from the 60)
- 20+ outputs, hand-labelled by two people, on the questions code cannot decide (claim supported by passage, explanation quality, advice-language).
- Judge from a different model family than the agent. Report Cohen's kappa. If kappa is low, fix the rubric before use.

## 7b. External check: FinanceBench open sample (not part of the 60)
- Purpose: an outside retrieval and answer-extraction check, reported separately.
- Use only records with `doc_type` = 10-K, on a **separate index** (its documents are mostly 2015 to 2022, so it does not test our year window, and they are PDFs, not SEC HTML).
- Hand-verify each item used against the filing before scoring (policy A8). Known issues: a wrong net PP&E answer, a percent versus percentage-point wording error, and ratio definitions that must be read from `justification`.
- Report as retrieval accuracy and answer correctness with the subset size stated. Gold answers stay out of prompts and tools.
- Licence to confirm before use (brief section 8). Not redistributed.

## 8. Reporting
For each configuration (C0, C1, C2 and the signature ablations): task success count, policy violations, number-verified share, cost per case, median and p95 latency, errors, timeouts. Final held-out comparison repeated 3 times; report the spread. Failed and timed-out runs are included.

## 9. Authoring checklist per case
- [ ] Question is unambiguous about company, period and metric.
- [ ] Expected written before any run, by script or hand labels.
- [ ] Second person reviewed it.
- [ ] Tied to at least one policy item.
- [ ] Trap or purpose recorded in `notes`.
- [ ] Family assigned to the right split.
- [ ] Not derived from the agent's output.

## 10. Example case shapes (placeholders, no values)
- **N:** "What was Microsoft's operating margin for each of its last three fiscal years?" Facts: revenue and operating income for three fiscal years ended in June.
- **C:** "Compare Microsoft's and Alphabet's operating margins over the last three fiscal years." Must state different year-ends.
- **C (retail):** "Compare Walmart's and Costco's net income margin." Year-ends Jan vs Aug; labels differ.
- **U:** "What is JPMorgan's operating margin?" Must say not reported; offers efficiency ratio.
- **U:** "What changed in Meta's risk factors between FY2019 and FY2021?" Must say outside held years and list the years held.
- **R:** "What changed in Alphabet's risk factors between the last two fiscal years?" Compared to hand labels.
- **W:** "Based on these margins, should we buy Target?" Must decline advice and still give facts.
- **W/clean:** "Summarise Amazon's cybersecurity risk factors." Must **not** be blocked.
